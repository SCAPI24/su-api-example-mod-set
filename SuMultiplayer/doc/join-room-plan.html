解耦硬规则（本步必须遵守）

#规则为什么
1socket 只能由 transport 持有两个模块各自收包会重复消费/漏包，且下线时无法归还
2世界状态唯一所有者是 session（主机侧经 host.authority）避免"两个模块都以为自己有权改世界"
3模块之间只通过端口 + 能力通信，零直接引用否则下线一个模块就是编译不过或空引用崩溃
4host.authority 声明为独占一个进程只能有一个权威；第二个申请者直接不可用
5日志、发现、队列都不得成为硬依赖它们挂了联机仍要能跑（日志写不进去就算了）
6新消息必须先进 wire 表 + 原子契约，才允许发送否则又回到"每条消息一套私有逻辑"的老路
7任何模块不可用时，状态要能在 UI/日志里看到原因"点了没反应"是最贵的 bug 类型
8客户端不下发权威结果，只发意图沿用旧实现的权威模型（AUT01）

文件格式与写入策略

照旧实现 + 一处必须改的文件名
项旧实现新方案原因
主机文件Logs/Server/ScMP-op-<日期>.logLogs/Server/SuMP-op-<日期>.log必须换名：Logs/Server/<日期>.log 被无头端 ServerAuditLog 独占句柄，旧注释明确写了"同文件二次打开会失败"
客户端文件Logs/Client/<日期>.logLogs/Client/<日期>.log沿用
行格式HH:mm:ss.fff event=… k=v同左便于两端按时间对齐
句柄单句柄；日期变化或角色切换时重开同左避免多次打开同一文件
刷盘每行 Flush()同左（可关，见下）崩溃时最后几行不丢；代价极小（人读日志量级）
失败处理全部吞掉，绝不抛同左日志不允许影响游戏
大小控制无（按天分文件）按天 + 保留 7 天 + 单文件 16 MiB 截断提示平板存储有限
根路径data:/Logs/…同左游戏自己的 storage 根，安卓 12 分区存储下才可写

与状态队列的分工

两条记录线，别互相替代
Journal（结构化）Logs/Server · Logs/Client（人读）
形态48 B 定长二进制 · 分段落盘文本行 · 按天一个文件
写频率每条状态变化（可采样 / 可只留内存）只写关键决策（加入、拒绝、分片完成、超时）
读的人程序：筛选 / 导出 / 回放人：直接看，贴工单
崩溃后块级 CRC 恢复，续写序号最后一行可能截断，靠 Flush 尽量少丢
关系同一条事件在 Journal 里落一条结构化记录，同时由 logRouter 决定要不要在文本里写一行 —— 用同一个 JournalCategory 判定，避免两套标准
本步的日志验收 平板加入成功后，主机 Logs/Server/SuMP-op-<日期>.log 里应出现 event=join.req client=… 与 event=transfer.chunk.serve client=…； 平板 Logs/Client/<日期>.log 里应出现 event=join.send、event=join.decision result=ok、event=transfer.done chunks=N。两端 seq= / client= 可对齐。

步骤与验收

步做什么只碰哪些模块验收（两端都要看）

4世界分片传输（复用 WorldTransferReceiver）transfer进度到 100%，校验失败可修复；主机记录 chunk.serve

每步都要做的三件事 ① 新消息先进 wire 表与原子契约；② 两端 Logs/ 有对应行；③ 用 ModuleHost 关掉本步模块，确认只掉这一个功能而不崩。

已知坑（本步会踩，先记下）

#坑对策
1平板 Game.log 每次启动被重写（实测只剩 46 行）分析用我们自己的 Logs/Client 文件；或用 logcat
2Logs/Server/<日期>.log 被无头端独占换文件名 SuMP-op-*，不要试图共用
3Comms 依赖要改两处（csproj + ModInfo）写进契约测试：两处声明的依赖集合必须相等
4Android force-stop 不触发 OnUnload关键状态照 Journal 恢复，不依赖收尾代码
5平板分区存储只用游戏 data: 根，别写游戏目录之外
6旧 mod 仍在 .uninst 但文件还在测试前确认只有 SuMultiplayer 是 .scmod，避免两套联机抢同一个入口
7部署脚本的 MSYS 路径坑（本地/远程路径语义相反）已固化在 deploy-sump.sh：cygpath -w + MSYS_NO_PATHCONV=1
