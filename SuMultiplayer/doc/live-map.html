每个格子 = 一个方块列（12.4 px/格）；颜色 = 该列最上层非空气方块，越亮 = 该列顶部越高。地形填充只来自主机 chunks[]（主机真正加载的区域；未加载处保持空白）。「居中角色」同时决定画哪些区块集合（图例与统计面板都写明「当前视图」）：选 Host（房主） = 地形只有主机 chunks[]，每个完整客户端的 clients[].chunks 都画成线框，并画出全部角色的标记；选某个客户端 = 只画它自己的线框（地形仍只取落在它区块集合内的主机 chunks[]），也只画它自己的标记。客户端当前内存区块 = 线框（每个区块一圈、不填地形；clients[].chunks 是客户端当前内存里的区块，已卸载的块立刻从图上消失），颜色 = 该块相对它自己那个客户端的校验状态：绿=已验证同步（s=2）、蓝=同步了主机端数据（s=4）、黄=已上报待裁决（s=1）、红=验证失败（s=3）；s=0（刚加载、尚未上报/裁决）是正常过渡，该块画中性灰线框、不报警；同一区块被多个客户端覆盖时线框**都画在同一条区块边界上**（与地形 16×16 严格对齐，不内缩），按身份稳定键排序只决定线宽（图例里写明规则）。标记标签给出角色的绝对坐标与区块：每个玩家角色槽位各一个标记 —— 主机自己的本机槽位是 Host#0 / Host#1 …（暖色），玩家端槽位是 <名字>#<槽位>（同格时按槽位顺序错开、不重叠）。动物（主机端） = 黑色实心圆点（仅位置：不显示名字 / 坐标、不可选中、不画连线；只来自 animals[]，客户端不贡献）。主机地形只填充、不画任何方框（chunks[].s 仍留在 feed 里，但页面不画主机侧框）；客户端区域线框是图上唯一的框层（粗实线 + 深色底衬）。旧参数 ?verify 仍接受但已忽略（不再有任何主机侧框可开关）。

为什么地图这么高？为什么有空的地方？ 画布高度 = 覆盖格数 × 12.4 px，不做任何钳制：地图盒子不再有 max-height 与内部滚动条， 整页跟着地图一起变高、由页面自己滚动。空白是故意不填色的：那里要么不在 /state 列出的主机 chunks 里，要么该列的 contents == 0（没有方块）。画面只呈现真实拿到的数据， 不用底色或推测地形去糊满空白，否则会让「未加载」看起来像「已加载的黑色地面」。地形填充只有主机已加载区域（chunks[]）； 主机地形只填充、不画任何方框。客户端当前内存区块只画线框、不填地形（clients[].chunks = 客户端的当前内存集合，卸载即消失）：绿 = 已验证同步（s=2）、蓝 = 同步了主机端数据（s=4）、 黄 = 已上报待裁决（s=1）、红 = 验证失败（s=3）；同一区块被多个客户端覆盖时线框**都画在同一条区块边界上**（与地形 16×16 严格对齐、不内缩），按身份稳定键排序只决定线宽。 区块正中的数字（chunks[].n）是"这个区块还有几个在线客户端没拿到最新内容"：0（都已核对到最新）或字段缺失时不画，绝不猜一个值。

数据契约与用法

怎么跑起来
先建房并加入房间，再启动 LiveMap 工具；页面默认轮询 http://127.0.0.1:8738/state，约 700 ms 一次（cache:"no-store"）
换地址：?url=http://127.0.0.1:8738/state；预选居中角色：?center=<key>（key = 身份稳定键，重连不变；旧写法 ?center=<id> 也认，只在第一个样本上生效一次，之后完全由工具栏的「居中角色」下拉框决定）；初始比例：?scale=6；?verify 是旧参数（仍接受但已忽略：主机侧不再画任何框，无需开关）
view = "all"（整个已加载区域，radius 为 0）或 "window"（旧的“角色周围 N×N 区块”窗口，用 radius）；两者都只画 chunks 里列出的区块
当前视图 = 「居中角色」的选择（图例与统计面板都逐字写明，只有一处代码决定这件事）：选 Host（房主） → 地形填充只有主机 chunks[]（主机真正加载的区域），每个完整客户端的 clients[].chunks 都画成按状态着色的线框，并画出全部角色的标记；选某个客户端 → 只画它自己的线框（不画其它客户端），地形仍只来自主机 chunks[] 且只限落在它区块集合内的那些块（别处的主机地形也不画），也只画它自己的标记。客户端区块没有地形载荷（d），所以它们永远不填地形——只画线框，绝不会被画成"已加载的地面"
bounds（chunkMin/chunkMax 或 cellMin/cellMax）给出覆盖范围，工具算的是主机区块 ∪ 各玩家端已加载区块的并集（boundsSource 写明来源）；缺失或为 null 时，页面用 chunks + clients + players 自己算范围，绝不猜地形。客户端视图不并入 bounds（那是主机的整片范围）：画布只按该客户端自己的区块与它自己的位置撑开，否则客户端的图会被撑成主机那么大
画布尺寸：半跨 = max(|charX-minCellX|, |charX-maxCellX|)（z 同理），画布 = (2×半跨+1) 格 × scale —— 多出来的那一格就是角色自己那一列，于是角色所在格精确落在画布正中；区域不对称时空的那一侧就留白。minCellX/Max 取的是本视图作用域内的区块范围，客户端视图里其它角色的位置不会扩画布
比例：默认 12.4 px/格；「－ 缩小 / ＋ 放大」按 ×0.5 / ×2 步进，滚轮微调；「整片区域」按浏览器窗口算出能把整个覆盖范围装下的比例
自动拟合：feed 数据（覆盖范围 / 区块集合 / 角色坐标 / 客户端区域）一有变化，页面自动执行「整片区域」（最多 4 次/秒）；数据没变不重拟合、不抖动。手动缩放（「－ / ＋」或滚轮）后保留 3 s，之后下一次数据变化恢复自动拟合
每个 chunk 的 d = base64(768 字节)：0..511 为 256 个小端 uint16 的 contents（下标 x + 16*z），512..767 为 256 个字节的该列最高非空气方块的绝对 Y
主机 chunks[] 的 s（黄/绿/红/蓝校验状态）仍留在 feed 里，但页面不再画任何主机侧方框（用户要求：主机端不需要任何方框，主机只保留地形填充）；?verify 作为旧参数继续接受但被忽略。客户端区块的状态不在这里：每条 clients[].chunks 条目自带它相对自己那个客户端的 s（[cx,cz,s] 的第三项：2 绿 / 4 蓝 / 1 黄 / 3 红 / 0 中性灰），画成客户端区域线框 —— 这是图上唯一的框层
每个 chunk 的 n = 还有几个在线客户端没拿到该区块的最新内容（主机侧内存计数，v5 追加）。n > 0 时在该区块 16×16 格的正中画一个数字（深色描边 + 亮色填充，地形再花也读得出）；n == 0（全部客户端都已核对到最新）或字段缺失（旧版主机/工具）时不画数字，也绝不猜一个值。这个计数不进存档：客户端加入时的整图下载就是最新基线，所以新加入的客户端谁都不欠；主机离开过这一块也不清零（客户端进来时仍要核对）。工具侧的统计是 counts.pendingMarks（有几块标了数字）与 counts.pendingClients（各块 n 之和）
watched = { id, key, name }（v6 起带 key = 被观察身份的稳定键）：工具当前观察的客户端，统计面板显示「被观察客户端：<name>（键 <key>）」；id === -1 时显示「当前没有客户端在线（没有验证状态）」
players[] = [{ id, key, slot, name, isHost, host, stableKey, cell:[x,y,z]|null, cellReason, chunk:[cx,cz] }]（v10）：每个玩家角色槽位一条 —— 主机自己的本机槽位 0..3（id=0 · key="0:0"/"0:1" · host=true）+ 每个联机化身的 (clientId, slot)。key = 角色键 clientId:slot；slot = 该设备上的本机角色槽位；stableKey = 身份稳定键（同一身份的所有槽位共用，「居中角色」按它选，重连不变）；host = clientId==0 的显式别名。cell = 该角色在世界里的真实绝对坐标（主机本机角色 = 它的 ComponentBody；联机化身 = 主机侧实体的 ComponentBody，不是按区块猜的）。标记标签：主机槽位 Host#0 / Host#1（暖色），玩家端槽位 <名字>#<slot>（槽位色）；同一格内多个角色按槽位顺序错开、不重叠；cell=null 时标记退回区块中心并写「坐标未知」+ 原因。画哪些标记也由「居中角色」决定：主机视图画全部角色槽位，客户端视图只画该身份的全部槽位。centers[] 仍是旧形状（每个身份一条，只带区块），旧页面继续可用
clients[] = [{ key, id, name, reported, currentLoaded, merged, complete, chunks:[[cx,cz,s]…] }]：该身份的「客户端当前内存区块」集合 —— v8 起 chunks 就是客户端当前内存里的区块（客户端实时把增删告诉主机），已卸载的块立刻从图里消失。key = 身份稳定键（与 players[].key 同一个键），id = 当前 clientId；工具按 key 合并条目，所以同一身份重连前后仍是一个条目。currentLoaded（v8）= 客户端当前内存区块数（= 本快照 chunks 的条数）；reported = 会话累计上报条数（只增不减，仅作参考，不是当前内存集合大小）；merged = 本次真正合并进来的条目数。每个条目是 [cx, cz, s]：s = 该块相对这个身份自己的校验状态（0 刚加载未裁决 = 正常过渡（不画线框、不报警）/ 2 绿 / 4 蓝 / 1 黄 / 3 红），页面据此画线框（每个区块一圈、只有描边、不填地形，线框下垫深色底衬，实线）。主机视图把每个完整客户端的当前内存区块都画成线框；客户端视图只取被选中的那一个。多客户端覆盖同一块：几何**都画在同一条区块边界上**（与地形 16×16 严格对齐、不内缩不偏移）；按身份稳定键排序，第 i 个线更宽（i=0 最细、画在最上层），颜色仍按各自状态。complete=false（merged !== currentLoaded：工具没把头部声明的当前内存条数全部合并起来）→ 整块区域不画、也不进线框集合，并在图例与统计里写明条数。条目只有 [cx,cz]（旧版工具）或 s 不认识（负数 / 小数 / 非数字；0 是正常值）→ 该块不画线框并在图例里明确报警（绝不猜状态）
animals[] = [{ x, y, z }, …]（v9）：仅主机端生物、仅位置（没有名字 / id / 状态）。页面把每只画成一个黑色实心圆点（半径约 2–3 px、随缩放轻微变化）：不显示名字、不显示坐标、不响应选中、不画标签 / 连线，与角色标记（彩色 + 名字/坐标）明确区分；客户端不贡献动物。counts.animals = 主机端动物数量（页面只做对照，以 animals[] 条数为准）；缺字段 → 不画动物并在图例里明说；条目的 x / z 不是有限数 → 该条不画并计数报警（绝不猜坐标）
payloadVersion = 10：LiveMap 线上的载荷版本（只追加字段，不重排旧字段）。页面按 v10 读字段（v10 = 新增 players[] 逐角色槽位清单（key=clientId:slot / slot / stableKey / host），于是主机槽位 0..3 与每个联机化身的 (clientId,slot) 都能画出来；v8 = 每个客户端头部 currentLoaded 且 clients[].chunks = 客户端当前内存区块；v9 = 新增 animals[]（主机端动物位置，仅 x/y/z）与 counts.animals；v9 = 新增 animals[]；v5 = 每个 chunks[] 记录末尾追加 n；v6 = watched / players / clients 条目追加 key；v7 = 每条 clients[].chunks 条目末尾追加 s，页面输出为 [cx,cz,s]；v8 = 每个客户端头部记录末尾追加 currentLoaded，且 clients[].chunks 的含义改为客户端当前内存区块（卸载即消失））；版本不符 / decodeFailures > 0 时在图例与统计面板里明确报警，不猜字段含义。缺字段（旧版主机/工具）时页面明说不画：没有 players → 坐标一栏写「未知」；没有 clients → 不画客户端线框；clients[].chunks 的条目没有第三项 s → 这些块不画线框（不猜状态）；没有 currentLoaded（旧版 v7 feed）→ 完整性退回按 reported 判定并在图例里明说；没有 chunks[].n → 不画数字；没有 key → 选角退回 id（旧版行为）；没有 animals → 不画动物并在图例里说明
counts = 工具统计：chunks / columns / players（= 角色槽位数，v10）/ hostPlayers（主机自己的槽位数）/ clientChunks 之外还有 pendingMarks（chunks[].n > 0 的区块数）与 pendingClients（各块 n 之和）；页面只做对照，不据此画地形
覆盖范围 = bounds ∪ chunks ∪ clients[].chunks ∪ players[].cell —— 但每一项都先按当前视图作用域裁剪：主机视图取主机 ∪ 全部完整客户端的并集与全部角色位置（于是能看到分开的区域块），客户端视图只取该客户端自己的区块与它自己的位置（bounds 与其它角色都不并进来）
center.cell 缺失（null）时，退回到所选角色的区块中心 chunk*16 + 8（并在图例与统计里标注「坐标未知，按区块中心画」）
颜色表按游戏方块 id（Survivalcraft/Game/*Block.cs 的 Index）校正，覆盖常见方块；未收录的 id 一律中性灰并在图例里标「未知方块 id」（不再用哈希色相兜底 —— 那会把雪原画成青色、把未知方块冒充成水）。水（id 18）另有独立的「水域」色阶。整片区域可能上万列，因此按 (id, 高度档) 批量填充、不做逐列描边，一次样本只画一次（不跟动画帧）
