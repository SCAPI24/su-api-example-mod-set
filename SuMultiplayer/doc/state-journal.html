目标

要解决什么

排障与复盘都需要"事后能看到"

三条硬指标

① 线性写入
O(1) · 零分配

游戏线程只做一次数组写入 + 一次序号发布；不排序、不加锁、不做 I/O。

② 快速存盘
分段追加 + CRC 块

独立线程顺序读序号区间，256 条一个块，4 MiB 一段；崩溃只可能坏最后一块。

③ 快速按类别筛选
位掩码 + 顺序扫描

16 个类别用位掩码；全量扫描 6.5 万条约 100 µs，"最近 N 条某类"走稀疏索引约 8 µs。

定位 它是诊断与复盘组件，不是游戏状态的所有者：状态仍归各业务模块，队列只记录"发生了什么"。 因此落盘失败时只计数、不抛异常、不阻塞会话。

内存

环形队列：写完就忘，忘之前先落盘

容量固定 → 常驻内存可控

环形写入（可播放）

写指针转圈，落盘指针随后追
写入

槽位 = 序号 & (容量−1)；容量取 2 的幂，取模变成按位与。

发布

先写槽位、再把序号用 release 写出去；读端 acquire 读序号后读槽位，不会看到半条记录。

覆盖

绕一圈后覆盖最旧槽位。若它还没落盘 → 计一次 OverwrittenUnflushed，不阻塞游戏线程。

序号与窗口语义

外部只认序号
成员含义谁在用
NextSequence下一条将写入的序号（单调，不回退）落盘端判断"还有没有新东西"
PublishedSequence已发布（内容可见）的最后一条筛选窗口上界、增量消费
OldestSequence仍在内存里最旧的序号筛选窗口下界、缺口检测
TotalAppended累计写入条数诊断面板
OverwrittenUnflushed未落盘就被覆盖的条数（>0 说明刷盘跟不上）背压告警（SEG03）
Reset()清空内存窗口，序号不回退退出房间 / 换世界
为什么序号不能回退 外部（落盘端、导出、UI 分页）都拿着序号引用。一旦复用序号，旧引用会指向新记录， 就会出现"翻页看到别的事件"这类无法解释的现象。

背压：磁盘慢下来会怎样（可播放）

调快写入 / 调慢磁盘，看积压与丢失
设计取舍 队列容量必须覆盖「写入速率 × 刷盘间隔」。覆盖不住时，丢最旧的未落盘记录并计数， 而不是让游戏线程等待磁盘——联机会话的流畅优先于诊断完整性（实测：容量 4096、突发 5 万条 → 落盘 4096、丢失计数 45904，游戏线程未阻塞）。

崩溃恢复（可播放）

撕裂的尾块被截断，序号从最后一条有效记录续写
① 逐块校验

从头读块头 → 校验 magic / 条数 / 字节数 / CRC32，第一处失败即停止。

② 截断

文件长度回退到最后一个有效块的末尾（实测：追加 3000 B 垃圾 → 截断 3000 B）。

③ 续写

续写序号 = 最后一条有效记录 + 1（实测：60000 → 60001），旧数据零丢失。

// 主机端（客户端只是换目录与 role）
var options = new JournalOptions { Directory = "data:/Journal/Host", Capacity = 1 << 16 };
var journal = new StateChangeJournal(options);
var writer  = new JournalSegmentWriter(options, journal);
writer.Start();

// 游戏线程：一次调用，零分配
journal.Append(JournalCategory.Terrain, JournalEventCode.TerrainCellsBroadcast,
    JournalRole.Host, JournalSeverity.Info, actorId: clientId,
    valueA: cells.Count, valueB: sequence, valueC: serverTick);

// 面板：最近 200 条被拒绝的操作
var spec = new JournalFilterSpec(JournalCategory.PlayerAction | JournalCategory.Region,
    minimumSeverity: JournalSeverity.Notice, take: 200);
foreach (JournalRecord r in journal.CreateFilter(in spec)) Render(r);

// 关闭 / 导出前：等落盘追上
writer.FlushAndWait();

顺带修掉一个真问题 改之前 FlushToDisk=true 在运行期是空操作：Drain() 只做 Flush()（刷到页缓存）， 只有 Dispose() 才真正 fsync。所以那时"开 fsync"测不出代价（0.46 ms/块是假的）。 现在改为每个刷盘周期末尾 fsync 一次（块级 fsync 会把吞吐打掉一个量级），实测 2.04 ms/次。
五条降频杠杆（3 条纯配置） ① 少写记录本身（只写合并后的原子 / 值没变不写 / 高频类采样）→ 效果最大； ② 加大块 RecordsPerBlock（↓4× 写次数）；③ 加大段 + 拉长间隔（↓轮转与 manifest）； ④ 关 fsync（只给账本类开）；⑤ 纯内存 + 按需导出。②–⑤ 全部是配置，不用改代码。
