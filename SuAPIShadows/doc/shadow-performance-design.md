# 角色阴影与帧开销优化设计

日期：2026-11-11。状态：本 Mod 内实施完成，Release 与混淆通过，已部署并完成游戏世界加载检查；视觉效果与帧时间仍需场景验收。本轮参考为用户提供的 `[SuAPI]Dawnrift Shaders-2.0.0.scmod`，包内 API 元数据为 0.1.7.0；反编译分析材料仅位于被忽略的 bin/ReferenceReview，不作为本 Mod 的依赖或提交内容。

## 已明确的需求

- 以降低额外帧开销和卡顿为优先目标；不追求高精度角色影子。
- 当前太阳照射地形的精度已被用户认可，保留其分辨率和视觉尺度。
- 角色影子应附着于真实可见的地面、墙面，不生成悬在天空中的黑色贴片。
- 保留局部灯光遮挡功能；不能把参考包的单纯增亮当作等价替代。
- 用户已明确：仅真正发光的部分不接收阴影。火把杆、灯座、LED 外壳仍正常接收阴影。
- 只改 SuAPIShadows，自有数据、缓冲和生命周期不依赖其他 Mod；需要主框架的部分通过单独协作文档交接。

## 参考实现与当前实现的实际差异

| 项目 | Dawnrift 参考 | 当前 SuAPIShadows |
|---|---|---|
| 角色影子 | GPU 骨骼模型深度写入 shadow map，实际表面采样 | CPU 抽样模型顶点，平面投影、凸包、接收面扫描和裁剪，再绘制黑色三角扇 |
| 太阳刷新 | 吸附中心、光方向、模型移动及近远刷新间隔 | 当前已缓存一张 512 图，但按时间整体重画 |
| 局部灯光 | 最多三个增亮参数，没有本方六面点光遮挡图 | 最多十盏灯，每盏六面，正常每 0.28 秒清空并重画整张 atlas |
| 模型资源 | 使用 InstancedModelsManager 缓存的 GPU 顶点和索引 | 已缓存原模型顶点，但接收面重投影、排序和裁剪仍耗 CPU |
| 精度控制 | 两级太阳图、不同精度及刷新节奏 | 太阳图 512、点光每面 96；按整体帧时长降低更新频率/选灯数量 |

参考的低开销不能全部归因于算法更优：它没有承担本方全部局部遮挡工作。也不照搬其仅根骨平移的变化检查、缺少地形完整失效链、静默 catch 或固定骨骼数截断。

## 当前问题的源码证据

1. `SubsystemDynamicShadows.UpdateModelSilhouette` 将角色骨骼顶点投到选中的平面，再建立凸包。`CreateReceiverPatches` 扫描范围内方块碰撞盒，对各面重复投影和裁剪。最后 `QueueSilhouette` 绘制独立黑色三角形，不是原地形着色器的光源可见性计算。
2. 当前接收面按碰撞盒构造，碰撞面与实际可见模型并不总一致；DepthRead 只会被已有近处几何挡住，不要求黑色几何背后一定存在接收表面。`QueueLayer` 还保留单次射线命中后绘制完整四边形的路径。以上能够产生悬空贴片，具体用户视角尚未录制复现。
3. `UpdateShadowTargets` 将局部光源方向的 Y 人为改为负值，并优先改用脚下接收面；这不是点光的透视投影。主角近身又绕过普通间隔而每帧重建，增加了开销。
4. `RenderTerrainPointShadowMap` 每次清空整张 atlas，然后最多十盏灯乘六面重复提交邻近地形；静止灯与未变化的地形也被重画。当前六个面共用同一份邻近 chunk 列表，缺少逐面的光空间视锥剔除。
5. `TerrainShadowShaders.TerrainPixel` 在纹理和顶点色合成后，将所有 RGB 统一乘阴影。现有距离光源 0.55～0.95 格的免阴影球体不代表发光材质，既会误保护墙面，也受选灯和朝向影响。

## 建议实施结构

### 角色改为低精度深度投影

- 通过公开 `InstancedModelsManager.GetInstancedModelData` 复用模型 GPU 缓冲，在深度 shader 中应用真实骨骼矩阵；移除角色专用的 CPU 凸包、接收面枚举和黑片绘制。
- 只有地形/目标接收表面的 shader 采样角色深度，天空没有接收几何，自然不产生黑片。点光按真实光源位置做透视投影，不强改投影方向。
- 太阳沿用当前 512 地形图；角色使用独立低精度动态深度层，建议先按 256 和约 12 Hz 的近处更新预算实施。静态地形与动态角色分开缓存，避免人物每动一次就重画大范围地形。数字属于待游戏内调整的起始设计，不是测得的最优值。
- 角色太阳深度与当前太阳投影使用相同坐标约定；点光角色层必须编码径向 distance/radius，不能复制太阳的 clip-z 编码。各层按每个采样位置的最小深度合并遮挡，不能把暗度反复相乘。
- 第一人称也准备真实身体和服装的骨骼，保存/恢复用于主画面的矩阵；不生成替身实体、不依赖额外眼睛/身体偏航修正，不截断不支持的骨骼。
- 遮挡者先按光源距离和光源视锥筛选，不能只看玩家视锥，画面外人物仍可能向画面内投影。
- 动态层每次完整清除其有效区域再重画，模型移除和离开光源范围也触发清理，不能追加旧影形成残影。

### 局部灯采用逐灯缓存和固定更新预算

- 保留稳定的光源身份和 atlas 槽位；每盏灯单独保存位置、范围、方向、覆盖区块以及有效版本。灯删除或换槽立即使旧记录失效。
- 静态地形阴影仅在光源变化、覆盖区块 GPU 几何变化、区块增删、设备资源重建时更新。不能只依赖 OnBlockModified：异步网格重建、流式加载和边界更新也要覆盖。
- 当前可读取 chunk 的 Geometry/Buffers、各 slice 的 GeometryHash/ContentsHash。实现时在绘制线程核对已提交 GPU 缓冲的身份与状态，不跨线程读取半完成的顶点数组；每次缓存仍绑定同一个真实几何版本。
- 不再 clear 整张 atlas。按一盏完整灯的六面为发布单位，clear 只针对该槽位；六面和矩阵完成后才对接收端生效。
- 每个相机每帧点光任务最多处理一盏灯的完整六面，静态/动态任务共用明确队列预算；优先附近且未有效的灯，并按等待时间避免远灯永久饥饿。另有限频条件，不能用“摊到每帧”反而增加每秒重画总量。
- 每个立方体面使用光空间视锥与 chunk/模型包围盒相交测试，减少重复 drawcall。相同光源的候选 chunk 集合可缓存。
- 先保留现有光源支持数量，不把减少支持灯数当作默认优化。若后续性能测量仍不足，再单独决定减少远处接收预算或点光分辨率；不得静默取消光源功能。
- 太阳只增加正确的变化检测和地形失效，保留用户认可的精度，不照搬额外远景级联。

### 精确保护发光部分

按用户选择，仅 `IsEmissive` 语义的面跳过接收阴影，并保留纹理、雾、alpha-test 等正常处理。杆、灯座及外壳不被豁免。删除基于距离的免阴影球，不能按 RGB 高亮猜测发光面。

LED 的亮点由原版 SubsystemGlow 单独绘制，当前并未经过地形阴影 shader；LED 外壳自身不是发光材质。需要在游戏内区分亮点与外壳，不把外壳受阴影当成发光面错误。其它模组或自发光材质同样以准确材质语义为准。

最终采用纯 Mod 发光三角形补绘：保留原 Block 类型，读取已初始化的真实模型，缓存 IsEmissive 三角形，以与地形相同的坐标/UV/雾化和 Equal 深度恢复原亮度。覆盖原生 Torch、亮 Lightbulb、亮 ChristmasTree 装饰、JackOLantern 发光面；LED Glow 沿用原生绘制。按方块生成/变更/卸载事件记录格位置，GPU buffer 变化后只重建该 chunk 的已知发光格，避免全区块逐格扫描。每可见有发光几何的 chunk 最多增加 opaque/alpha 两次绘制。未修改主框架、未替换原版 Block、未使用 alpha 位私有编码。此前框架协作请求保留为通用第三方材质的可选接口建议，不再阻塞本轮。

## 性能判断与验收

当前静态点光单次最多 60 面，单帧点光队列预算为 6 面时可限制提交峰值；这是提交数量约束，不能直接换算成 FPS 百分比。静态灯且地形未变化时，缓存建立后可不再重绘静态地形，检测成本仍存在。动态层会增加少量绘制和采样，应与删除的 CPU 投影及地形重画成本一起测量。

最终在指定游戏宿主内、同一世界与位置比较修复前后：

- 静止场景与人物原地动作、走动、转身；第一/第三人称、不同衣物、多生物。
- 平地、墙角、坡面、悬崖和镂空模型；火把在人物下方/侧面/上方，天空不出现黑片。
- 单灯、多灯密集区；放置/破坏/开关灯、区块加载卸载、设备重建后无残影或过期缓存。
- 火焰/亮灯头/LED 亮点不变暗；火把杆、灯座、外壳及相邻墙面仍受阴影；关灯状态正确。
- 相同画质与视距记录平均帧时间、P95/P99 帧时间和光影相关提交数量，尤其观察周期性长帧。诊断数据按需采集，验证后移除，不在热路径刷日志。

本轮已完成 Release Rebuild 和 Obfuscar（0 警告、0 错误）、ZIP/CRC/哈希校验并替换目标包。实际游戏单实例成功进入世界，当前运行日志无 SuAPIShadows 初始化或绘制错误。尚未做修复前后同场景帧时间对照，不承诺 FPS 数值。

## 最终实施差异与边界

- `ModelShadowRenderer` 使用真实模型 GPU 缓冲和骨骼，原 CPU 凸包、角色接收面扫描、黑色贴片路径已移除。人物准备最多 12Hz；实体增删立即失效，第一人称身体与衣物使用身体计算视图并恢复原骨骼数组。
- 太阳静态图保留 512；角色远处图256保留宽范围，另有512/24格近处图，边缘渐变到远图。角色约3厘米、地形约18厘米独立偏移。静态检查光方向/锚点/GPU几何变化，人物动态不强制重画地形。
- 点光静态 atlas 每面96、动态每面64，保持最多10槽。稳定槽位、GPU缓冲快照、逐面视锥剔除；每相机每帧最多一个灯任务。普通动态任务6面；同灯静态也脏时是6静态+6动态，共12面，不把总预算虚报为6面。
- 太阳角色近、远层使用四tap手动bilinear PCF，近图内部只采近层，边缘才同时采两层。点光静态/动态两层各2tap，最多4读取/灯。新增近图的质量与成本应在游戏中测量，不宣称完全无开销。
- 发光补绘是原生已核实模型契约，不能自动复原任意第三方重写的 GenerateTerrainVertices；遇到不兼容覆写明确报错，不暗中替换方块或猜网格。WickerLamp并无原生 IsEmissive 网格，LED外壳也不被标为发光。
- 渲染调度器原本吞掉异常；本Mod现在记录首次绘制失败并在更新边界报告完整日志/弹窗，停止故障路径，不继续伪装成功。
- 未添加角色替身实体、跨Mod引用或新的平台目录。整个改动仅位于 SuAPIShadows。

## 手持物接入

手持物复用角色深度图和12Hz姿态准备预算，通过真实Block.DrawBlock批次捕获而非模拟实体或包围盒。每次采集比较实际几何并缓存GPU缓冲，每个光源/面只提交缓存；空手、死亡、切换、移除与设备恢复均有失效或释放处理。没有新建阴影图。原生批次纹理和alpha语义单独保留，避免把透明物品图标投成整块矩形。改动位于ModelShadowRenderer、HeldItemShadowRenderer、HeldItemDepthShader；不改原版ComponentHumanModel。
