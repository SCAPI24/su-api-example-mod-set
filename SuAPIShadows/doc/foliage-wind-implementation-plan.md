# 植被风动与移动扰动实施方案及实现记录

日期：2026-11-11。已补充用户本轮确认的花、农作物、灌木、水下植物、季节主风向、生物经过与内存开关要求。状态：已按用户授权实施，使用最新 NuGet 0.2.1.0 编译、混淆并部署；原世界加载和内存开关的宿主内检查通过，完整场景与性能对照仍待验收。已完成的 WatchMod、SuAPIShadows、MemoryBankDrawMod 修改先提交于 Mod 集仓库 `76ecf7f`；本文保留审阅方案并在文末记录最终实现差异。

## 1. 目标与推荐路线

在当前 SuAPIShadows 内加入草、树叶、花、农作物和灌木的轻微风动；陆生软植被还对附近角色、动物经过作出短暂摆动。水下植物不接受空气风，只对附近涉水移动产生的小幅水波扰动作出反应。保留已确认正常的人物、动物、手持物投影和发光面处理。

优先降低额外帧开销，保留原有植被形态，不增加树叶面数、细分网格、替身实体或流体物理系统。风向、季节强弱和局部经过效果使用有明确预算的视觉近似，不模拟完整气象与水动力。

**推荐第一版使用纯 Mod 路线，不修改主仓库；按本轮指令改用已发布的最新 NuGet。** 继续以 .NET SDK 10、net10.0、Engine/EntitySystem/Survivalcraft 精确 `[0.2.1.0]` 构建。现有方块替换入口完成生成阶段标记，当前 Shadows 渲染流程消费标记并执行位移。

第一版采用“可见植被连续摆动、阴影按明确的低频相位/扰动快照更新”的质量策略，允许小幅影子滞后，避免每帧重画地形和全部点光图。该质量取舍已按方案实施，完整观感仍需实机验收，不是错误时的降级路径。

保留一个独立的**内存总开关 `VegetationMotionEnabled`（概念名称）**，覆盖空气风、陆地经过摆动和水下扰动。关闭时回到当前只有光影的效果，不写配置文件、不新增设置界面。性能成本尚未实测，不能先认定可以忽略后删除这个边界。

## 2. 已确认的首版范围

| 对象 | 确切原生范围 | 预期效果 |
|---|---|---|
| 草 | TallGrassBlock，含大小草状态 | 根部固定、上部随风；角色和动物经过时轻微压弯/回摆 |
| 树叶 | Birch/Mimosa/Oak/Poplar/Spruce/TallSpruce LeavesBlock | 连续的小幅空气风动；不加入角色经过导致整树抖动 |
| 花 | RedFlowerBlock、WhiteFlowerBlock、PurpleFlowerBlock | 花茎与花朵随风并响应附近经过；幼苗状态保留 |
| 农作物 | RyeBlock、CottonBlock 的野生/种植及各生长阶段 | 整株柔软部分随风和附近经过轻摆，保留原生生长、颜色与掉落 |
| 南瓜类作物 | PumpkinBlock、RottenPumpkinBlock 继承的生成逻辑 | 仅幼苗/叶片的交叉面摆动；实体果实、底座与不生成叶片的成熟状态不乱动 |
| 灌木 | DryBushBlock、LargeDryBushBlock | 小幅风动与经过扰动，比高草更硬、位移更小 |
| 水下植物 | KelpBlock、SeagrassBlock | 空气风权重严格为零；仅附近角色或动物在水中移动时，小幅、短暂摆动 |
| 固定部分 | 树干、泥土草皮 GrassBlock、FallenLeavesBlock、实体果实 | 保持原状 |
| 任意第三方植被 | 不按名称、贴图或颜色猜测 | 后续明确其类型/生成契约后再接入，不静默占用其他Mod替换点 |

以上约18个具体原版方块类型均纳入计划，**花、农作物、灌木不是只登记类别，而是要实际产生飘动效果**。南瓜仅柔软幼苗/叶片参与，不能让整个果实像草一样弯曲。

水下效果指植物响应一个局部、衰减的视觉水波影响，不包含修改原版水面网格、增加水波贴图或改变液体流动。没有水中移动来源时，水草在本功能下保持静止；雨、季节风和岸上行走不直接驱动水草。

所有位移仅影响渲染；不改变方块 ID、存档、碰撞盒、掉落、生长、电路或交互判定。

## 3. 挂载与多 Mod 边界

通过现有 `IModInjector.RegisterBlock` 为上述明确列出的植被方块索引注册派生类，在 `BlocksManager.Initialize` 生命周期按实际 API 契约接线。派生类仅包围原生 `GenerateTerrainVertices`：记录生成前范围、调用原生生成、给本次新顶点增加风动标记。方块基础属性、初始化时机和季节行为按原版保留，不手工重造整套方块数据。

必须明确这条路线的兼容限制：同一索引的 Block 替换不会自动组合多个 Mod 的覆写。若已有 Mod 替换同一个草/树叶类型，初版应明确报告冲突和方块索引，不能按加载先后静默覆盖，也不能把对方类型伪装成原生类型。后注册者覆盖本 Mod 时同样需要检查最终类型；当前注入 API 的冲突回调异常传播应在实施前针对实际契约核实。

着色器修改直接整合进当前 Shadows 已持有的地形及深度着色器，不再新增另一个 Mod 抢写 `TerrainRenderer` 的 shader 字段。主程序集不引用参考包，不新增跨 Mod 依赖。独立第三方光影 Mod 同时接管同一 shader 仍属于明确的冲突边界，不能承诺天然共存。

## 4. 顶点标记、锚定与线程规则

当前 `TerrainVertex` 只有位置、UV、Color，没有植被类别、根部权重或水陆介质。纯 Mod 首版拟用**已知原生不透明顶点的颜色 alpha**保存类别和位移权重，统一编码/解码，类别至少区分软草/花作物、灌木、连续树叶、水草。原始材质透明度仍来自原纹理；标记不是额外透明效果。

- 陆生软植物按明确的格内高度设置根锚权重，底边为零、上端较大，必要时平方形成弯曲。不能直接用 `fract(worldY)`，整数高度的顶点也可能是顶部。
- 花、黑麦、棉花的生长状态保留原版几何；小苗采用更小位移。南瓜只处理新增 `SubsetAlphaTest` 幼苗/叶片，不标记同时生成的 `SubsetOpaque` 果实。
- 灌木使用更小的刚度系数；树叶采用连续世界位置位移场，共用顶点在相同世界位置得到相同位移，防止面缝和区块裂缝。
- 水草独立标记，不进入空气风计算。Kelp/Seagrass 在原生生成植物交叉面后还调用水体基类生成水面，**只标记植物新增的 AlphaTest 顶点，不标记透明水面**。
- 多格高海带需在生成/缓存阶段确认同一植株的根和连续茎段，使高度权重沿整株连续，不能每格单独从零锚定形成折断或接缝。此判断只发生在几何生成与失效重建时，不每帧扫描水柱。根部、茎段或总高度变化时，同柱相关茎段的标记和缓存要一起失效，不能只重建被修改的单格。
- 无标记的普通顶点位移严格为零；有标记的顶点先还原不透明 alpha，再执行纹理 alpha-test、雾与颜色处理。遇到其他Mod已有标记或非原生透明语义时明确报告，不覆盖未知数据。
- 生成前后的 subset 对象按引用去重。`AlphaTestSubsetsByFace` 的多个元素可能指向同一个 Subsets[5]，不能反复标记同一范围。
- 生成线程仅处理本次新增顶点、读取不可变参数；不访问相机、GPU、Body 集合或共享可变状态。环境、移动源和时间的快照在游戏/绘制线程更新，不每顶点反射、逐帧回读 GPU 或重建地形。

当前自发光采用独立补绘，没有占用地形 alpha。编码常量、类别/根锚权重精度和剩余取值必须先完成位数分配并对照所有 shader；不能未经验证就承诺类别、整株海带权重、海拔等所有数据都能塞入单字节。海拔增强优先由原始世界 Y 在 shader 中计算，不重复占位；若所需根锚精度确实超出编码能力，应在实施前明确调整表示方案，不静默截断。不把私有取值发布成未经协调的框架公共协议。

## 5. 风向、季节与移动扰动

### 5.1 稳定主风与自然阵风

用户希望风向每次大致相同。首版以世界稳定的日月视运动轴作为东西方向参考，再由真实 `SubsystemGameInfo.WorldSeed` 给一个很小的固定偏角，得到世界主风向。同一世界重进后方向可复现，不按进入时间随机，不读取系统日期。

日月轴参考现有天空的运动计算，**不直接追踪太阳/月亮当下的水平位置向量**，避免正午、日落或换成月亮后突然反向。昼夜加热只允许围绕主方向缓慢小幅偏转，季节也只作轻微平滑偏转。这里借鉴地球的稳定盛行风概念，不计算纬度气压、科里奥利力、完整海陆风或月球潮汐。

“高山风”首版表达为稳定主风与有限的海拔强度增强：在既有地形生成阶段根据植被真实海拔保存或计算受风权重，高处可稍强；不对每株查坡向，不每帧发地形射线或求山谷气流。海拔基准及上限集中为可调参数，不能宣称这是物理准确的山风/背风坡模拟。

自然风使用少量低频波作阵风，世界位置只改变相位和很小的方向扰动。建议自然偏角约±6°、昼夜偏角约±5°，总方向围绕稳定主方向变化，不来回180°摆动。静止大范围场景可以看到一致主风，但不是全屏同步齐步摇摆。

### 5.2 季节为主、降雨辅助

读取 `WorldSettings.TimeOfYear` 与 `SubsystemSeasons.Season/TimeOfSeason`，不用现实春夏秋冬，也不要求世界必须开启季节变化。固定季节世界维持该季节强度。

建议相对强度起点如下，仅用于初版视觉调参：

| 季节 | 相对强度 | 视觉取向 |
|---|---:|---|
| 春 | 0.70 | 温和、带少量阵风 |
| 夏 | 0.55 | 较轻，避免农田持续剧烈晃动 |
| 秋 | 0.90 | 略明显，但仍保持小幅 |
| 冬 | 0.80 | 稳定偏强，不能无限叠加天气 |

按年内进度在季节系数间平滑插值，不能跨季瞬间切换。季节影响应明显大于日常雨量增幅。建议局部下雨最多增加约15%，高海拔最多约20%，阵风再有受限的小幅变化；最终位移仍按植物类别硬上限限制，不把系数连续相乘到失控。

`PrecipitationIntensity` 包含雨和雪，不能单独把它当成下雨。按低频环境查询读取 `SubsystemWeather.GetPrecipitationShaftInfo` 的实际类型与强度：首版只有 Rain 增强，Snow 维持季节基线；不因相机进入雪地而让整个世界风强度跳变。纯 Mod 首版在各视图附近的已加载位置低频采样降水类型，并平滑局部增强；这是每视图的视觉近似，不增加原生逐 chunk 参数钩子、不逐顶点查天气，也不宣称精确还原同一画面内每格的雨雪分界。环境过渡只影响小幅辅助增益，世界稳定主风和季节系数保持一致。

### 5.3 角色、动物经过陆生植物

高草、花、柔软农作物和灌木在身体附近受到轻微的局部压弯/回摆，根部仍固定。它是经过引发的视觉扰动，不新增碰撞、力学实体或改变植物生长；树叶、果实、树干不响应脚边经过。

使用现有 `SubsystemBodies.FindBodiesAroundPoint` 的8格空间桶做低频候选查询，再精确过滤：

- 只接受有效的角色/动物（有真实 `ComponentCreature` 的实体），不用所有 ComponentBody 作为来源。
- 检查三维距离、身体高度重叠与实际水平位移/速度；静止者不持续制造新扰动。
- 通过真实位置差和速度抑制传送/加载跳变，不从旧位置到新位置画穿越世界的拖尾。
- 轻微沿移动方向/离开身体方向弯曲，经过后在短时间内衰减复位，不做草永久倒伏。
- 水中角色不向岸上无接触的植物发送整圈空气风；交互只在身体所在局部高度与介质内生效。

建议查询10Hz，每视图当前活动来源最多4个，额外短迹最多4条；**水陆共用总数8条，不能各占8条**。稳定选择附近/相关来源，避免每帧随机换源；超过预算时按距离、影响量和年龄选取并淡出，明确只表现附近有限来源，不承诺全世界所有动物同时影响。

### 5.4 水下植物的水波扰动

水下植物的空气风系数始终为零。只有附近来源满足 `ImmersionFactor` 有效、`ImmersionFluidBlock is WaterBlock`，且确实移动时，才产生水下扰动；岸上走路、静止站水中、熔岩浸没和仅相机移动都不能触发。

扰动使用来源位置、移动方向/速度以及短迹年龄，计算一个范围有限、径向传播并逐渐衰减的视觉水波。强度随距离、深度差和时间下降。角色和动物涉水均可成为来源，近处才处理；未启用全局水流场或空气风穿过水面。

建议影响半径约2格、最大摆幅约0.025格、持续约1.2秒；没有来源时严格回到零。海带茎段连续弯曲，底根固定；海草局部轻摆。来源记录需设最小位移/时间间隔，不每渲染帧生成一条新水波；水下记录与陆地记录共享硬预算。

单靠八条位置/半径 uniform 不能保证隔墙、不同楼层或相邻独立水池完全隔离。首版必须写清：这是近距离视觉近似，要求三维高度/深度和水介质过滤；不能宣称完整水域连通检测。若用户要求严格隔开相邻水池/厚墙，应另加局部连通或阻挡判定并重新评估成本，不能用隐藏全域扫描补上。

### 5.5 视觉位移与计算预算

| 类别 | 建议最大水平位移（包含所有叠加） |
|---|---:|
| 高草 | 0.10格，普通风起点约0.06～0.08格 |
| 花、黑麦、棉花、作物叶片 | 0.07格；幼苗按身高减弱 |
| 灌木 | 0.04格 |
| 树叶 | 0.03格 |
| 水下植物 | 0.025格，仅水波扰动 |

这些是待验收的起点与硬边界，不是已测得最佳参数。风、阵风、身体经过和余波先合并，再受类别最大值约束，保证包围盒和预算可确定。

环境/来源状态低频计算，shader 每帧只消费已准备的有限 uniform。移动影响循环仅在已标记且位于交互近区的顶点执行；远处陆生植被只算基础风，远处水草不做本功能位移。每世界统一推进时间和来源，多个相机不重复推进同一条余波。

时间明确使用受世界暂停控制的 `SubsystemTime.GameTime`，不用 `Time.RealTime`；联机世界若本来未暂停，则按真实世界时钟推进，不由本 Mod 另造暂停状态。各波频率与周期边界要成套设计，短迹用游戏时钟记录年龄，不能只对总时间任意取模导致断相位。转换 float 前进行无跳变的周期处理。每视图最多8条记录，世界共享追踪池建议最多32条，固定数组/复用缓冲，不无上限累积轨迹。

## 6. 主画面与现有阴影如何配合

共同的 GLSL 风函数接入三条地形顶点路径：`TerrainVertex`、`ShadowMapVertex`、`PointShadowMapVertex`。深度 shader 新增颜色语义输入以识别植被；没有标记的方块位移严格为零。

主画面使用本帧连续风相位与已准备的陆地/水下影响快照。位移后的世界坐标必须统一用于最终投影、雾、太阳/近角色接收坐标及点光接收坐标，不能只移动 `gl_Position`，留下静止的世界位置参与光照。

**阴影缓存采用低频快照：**

1. 每份太阳静态图和每盏点光静态槽位记录本次完成的风相位、总开关版本和扰动快照；不能深度用空气风、画面却用水波。
2. 已有地形、灯位置、资源和区块变更继续正常失效；风相位和来源位置不进入每帧几何版本号，不能每经过一只动物就强制重建所有含草区块。
3. 仅覆盖实际存在非零位移的已标记植被阴影区域增加刷新期限：无水下扰动时，水草不触发风期限。建议首版太阳最多2次/秒、每灯最多1次/秒，具体受现有任务队列限制。
4. 点光同一灯六面必须使用完全相同的风相位/介质/来源快照，六面完成后一起发布；仍保持每相机每帧最多一个完整灯任务，不因风动一次重画全部灯。
5. 没有植被的太阳覆盖区/灯覆盖区继续复用原缓存，不额外定时重画。
6. 生物经过或水波的短时影响也可能比阴影快照更早出现/结束，不能据此宣称每次瞬间摆动都有逐帧投影。可见植被与最后完成阴影快照存在时间差。小幅位移、低精投影和现有柔化用于控制观感，但不宣称完全逐帧同步；如果用户要求阴影同步精度更高，需要重新确定刷新预算或另审动态植被层。

已存在的角色近/远动态太阳图、点光角色层和手持物缓存保持自身刷新规则；不为了风动提高人物12Hz准备频率。发光面补绘不使用植被标记，火把亮度也不随本功能调整。

## 7. 裁剪、缓存与生命周期

风动后的顶点可能超出原区块包围盒，主画面和阴影都要做保守裁剪。

- 原生主画面通过公开 `TerrainChunk.BoundingBox` 做视锥筛选。Mod 可在主地形绘制前按最大风偏移临时扩大 bounds，绘制结束恢复：扩张从保存的原值计算，不能每帧累积扩大。
- 若采用此共享运行时字段方案，需核对其他消费者的绘制顺序、并发读取和所有权；恢复时不能覆盖另一 Mod 后写入的 bounds。仅扩大本 Mod 阴影视锥的测试盒不足以解决主画面边缘闪隐。扩张必须实际覆盖原生 `TerrainRenderer.PrepareForDrawing` 的筛选时段，而不只是包住本 Mod 的绘制函数；实施前核对既有 DrawOrder/事件的开始与恢复边界，若无法正确包围，先报告入口问题，不把该项算作已完成。
- 范围/距离筛选同样应保留最大位移余量，不能仅扩 AABB 却在距离门槛处提前删掉区块。
- 是否含植被由生成/缓存阶段准确记录；地形生成线程提交结果时保留实际几何版本，不靠每帧扫描整块地形。区块卸载、重建、设备重置及世界退出必须清理对应记录。
- 首版无独立风动 RenderTarget、无逐叶新增 drawcall；增加的是标记顶点的 GPU 算术和含植被阴影的有限频重画。静止但有风的场景不再是“阴影零重绘”，这一成本必须实测。

## 9. 如需多个独立 Mod 共同控制植被

纯 Mod 首版的方块和 shader 接管点不是通用组合接口。若后续目标升级为“多个完全独立 Mod 对同一块追加顶点效果，彼此不覆盖”，建议再单独设计：

- SuAPI空间内的顶点生成装饰器注册表与生命周期；原版 `TerrainUpdater` 调用 `Block.GenerateTerrainVertices` 的边界设置很小的调用入口，传入实际类型、value、坐标、生成范围和线程上下文。
- 公共材质/顶点标记分配及组合契约，避免每个Mod私占同一alpha值。
- 地形主shader及深度shader的效果组合/参数更新契约，保证同一位移进入可见和投影路径。

生成入口少量几行并不等于整个框架能力只有几行；没有 shader 组合规则，也不能只靠生成hook保证多Mod兼容。若引入新GPU属性，则还涉及TerrainVertex布局与带宽，不属于最小的纯Mod方案。本轮不实施这些框架接口。

## 10. 内存总开关与性能边界

保留 `VegetationMotionEnabled` 总入口，关闭时只有当前光影，开启时才执行空气风、经过摆动和水下扰动。首版不新增配置文件、保存字段或设置界面；默认值在实现后通过同场景开关对照再确定，不能因为“GPU只算几个正弦”就宣布整体开销可忽略。

关闭行为必须包括：

- shader 的所有植被位移为零；标记 alpha 仍正确解码，不破坏现有透明和光照。
- 停止季节/风环境工作、附近 Body 查询、新轨迹产生和风/水波造成的周期阴影失效。
- 清除移动余波；关闭再开启时从当前有效身体位置重新采样，不接上关闭前陈旧轨迹。
- 关闭切换时对之前变形过的阴影槽执行一次正常队列失效/重画，恢复静止植被投影。此一次性清理不能省略，否则关闭后仍残留风动影。
- 地形缓存继续工作，不因开关而卸载/重注册方块或重建全世界网格。主画面包围盒恢复原值；资源恢复遵循既有所有权规则。

基础GPU位移本身可能较轻，但更多植物顶点、附近来源循环、季节/天气查询、短迹管理和植被阴影重绘都可能增加开销。只有平均帧时间和P95/P99、提交数及显存对照后，才能决定是否长期默认启用。即使实测开销较低，总开关入口也保留，方便后续按平台或效果决定，不必重写主体。

所有新功能共享原渲染/更新预算：环境建议1～2Hz，来源查询10Hz，最多8条每视图、32条全世界追踪记录，原角色12Hz预算不变。CPU端不逐植物查Body，shader端不遍历全体动物；没有额外植被RenderTarget、水面波纹贴图或物理模拟。发生错误应明确报告，不以自动关闭效果冒充正常配置。

## 11. 游戏内验收

在指定Windows游戏宿主验证，避免以独立运行Mod或纯配置检查替代画面验收。

- 高草、小草、花、黑麦、棉花、南瓜幼苗/叶片和两类灌木确实飘动，根部固定，生长阶段保持正确；果实不弯曲。六种树叶颜色/季节状态正确，无整块跳动、接缝或区块裂口。
- 不改变普通方块、树干、草皮、落叶、火把/LED、角色和手持物的几何与亮度。
- 同一世界重进后主风向大致相同；正午、日落和日月切换不180°反向；春夏秋冬连续过渡，雨增强小于季节差异，雪不误当雨。
- 人和动物经过草丛/花/作物/灌木时局部轻摆、停止后回弹；静止、传送、远处或不同高度的动物不制造持续全场影响。
- 水草无空气风；岸上经过、静止入水和熔岩不驱动水草；真实涉水/游泳经过时小幅摆动，余波衰减，多格海带不产生格间断裂。
- 关闭总开关后只剩正常光影，来源查询停止，旧风动阴影经一次队列清理消失；重启开关不恢复陈旧轨迹。
- 日间太阳与夜间多灯场景都能看到随快照更新的植被影，点光六面不混用不同风相位；可接受的滞后由用户确认。
- 大世界坐标、长时间运行、暂停、加载/退出世界、设备重建、草/树叶放置破坏后没有错误缓存或时间跳变。
- 屏幕边缘、区块接缝、视距边缘不提前裁掉摆动顶点；关停或卸载时资源/包围盒恢复正确。
- 同一支持方块被其他Mod替换时明确报告，不静默丢失任一Mod行为。
- 同一场景比较开关风动后的平均帧时间及P95/P99，记录阴影重画量与CPU尖峰。未测量前不承诺固定FPS提升或零开销。
- 按仓库规范清理游戏进程后串行Release构建、混淆，包结构/CRC/哈希核对，再替换单一对应scmod；不提交临时诊断日志。

## 12. 已确认内容与仍可补充的取舍

已明确纳入：草、六类树叶、花、农作物、灌木实际风动；水下植物只有近处移动水波；稳定主方向、季节主导强弱、雨天轻度增强；人和动物经过软植被；保留无配置文件的内存总开关。

仍需在实施/验收时检查的取舍：

1. 风动仅为稳定主风、海拔增强和少量自然偏转，不计算真实坡向/山谷气流；日月运行轴只是方向参考。
2. 是否接受可见植被连续运动、阴影低频更新的时间差，尤其短暂经过和水波可能不逐次出现在阴影图中。
3. 是否接受局部水波的视觉近似，或要求相邻水池/墙体严格隔离；后者需要增加连通/阻挡信息和成本预算。
4. 以本文小幅度为起点，结合实际植物大小调节；开关默认值待同场景性能比较后确定。
5. 第三方同索引植被/光影Mod需明确组合目标，不能声称任意替换天然兼容。
