# 框架协作：保留地形自发光材质语义

日期：2026-11-11。状态：可选的通用第三方材质接口建议；本轮已改为纯 Mod 原生发光三角形补绘，不要求框架配合，也未修改主仓库。

## 用户确认的目标

光影只豁免真正发光的部分，火把杆、灯座和 LED 外壳仍接收阴影。Mod 之间保持独立兼容，避免让光影 Mod 独占替换原版 TorchBlock、LightbulbBlock 等类型。

## 已定位的信息丢失

- `Survivalcraft/Game/BlockMeshVertex.cs` 已有 `IsEmissive`。
- `Survivalcraft/Game/BlockGeometryGenerator.cs:GenerateMeshVertices` 在约 605 行读取该值，发光顶点不乘原版环境亮度；约 614 行写入 TerrainVertex 后没有保留它。
- `Survivalcraft/Game/TerrainVertex.cs` 当前仅 Position、UV、Color，声明的布局为 20 字节；没有发光/材质标志。
- 后续光影 shader 无法从 RGB 唯一反推出发光面；将整块、整模型、光源周围半径或所有高亮颜色豁免都会误伤非发光面。
- TorchBlock 的杆与 Flame mesh 本来已正确设置 false/true；LightbulbBlock 的亮灯头与灯座也已区分，优先保留这份已有信息。
- LED 亮点由 SubsystemGlow 独立绘制，不应把 LED 外壳重新标成 emissive。需要区分开关灯头、发光部分、普通底座。

## 请求的最小公共契约

为最终地形绘制消费者提供准确、稳定的发光材质标志，并让原生普通渲染维持原有颜色、透明和雾效果。可以由框架确定具体存储/扩展接口，但应满足：

1. 标志来自实际源 BlockMeshVertex.IsEmissive，跟随每个输出顶点/对应三角形经过地形生成、裁面、合并、GPU 缓冲上传，不按光源距离或颜色猜测。
2. 没有自发光语义的普通地形、方块体和灯座明确标为非发光；亮灭状态变化随对应地形网格正常重建。
3. 不覆盖已有透明 alpha、材质 alpha-test 或其他 Mod 的标记。若利用现有通道编码，必须明确公共位定义、消费者解码和默认着色器兼容，不能由光影 Mod 私占 alpha 值。
4. 多 Mod 可消费同一份真实材质语义，不要求逐个注册方块派生替换、不改变已有方块 ID/碰撞/电路功能、不新增跨 Mod 依赖。
5. 地形工作线程只生成数据，GPU 上传和渲染在原有线程边界完成；设备重建、chunk 加载卸载和网格重建均保留正确标志。不存在标志错配到旧缓冲的窗口。
6. 控制顶点带宽成本。当前 TerrainVertex 为 20 字节，不直接假定 padding 足够；若增加字段/改变布局，应评估全体地形开销及 Windows/Android 两端 GPU 兼容。
7. 给出消费者可编译的确切 API/vertex semantic、启用与资源生命周期约定，以及包含它的 NuGet 版本；如果契约变更需要新版本，应明确发布，不复用旧包后让消费者盲猜布局。

这是一项为了多 Mod 兼容而选择的框架协作。专用 Mod 替换某些原版 Block 可以自行编码，但会占用替换点且无法自然覆盖任意第三方发光材质，因此不作为本次通用方案。

## SuAPIShadows 接入职责

拿到契约后，地形 shader 仅对非发光接收部分应用太阳/点光阴影，对发光部分保留原纹理和颜色，再执行原有雾化与 alpha-test。移除目前依据距灯 0.55～0.95 格决定免阴影的代码；不会给相邻墙体开免阴影区域。LED Glow 继续使用独立原版发光绘制，不重复加暗。

角色低精度深度投影和逐灯缓存不需要新增 Block 替换或私有方块语义；它们的设计见 [整体方案](shadow-performance-design.md)。

## 框架侧与联调验收

- 火把模型的火焰真、杆假；灯泡亮灯头真、灯座假；关灯头恢复正常阴影。
- LED 亮点正常发光、外壳正常接收；相邻墙面没有随灯一起被豁免。
- 雾、半透明、alpha-test 与无光影 Mod 的原版画面一致。
- 方块变更、区块卸载重载、GPU 资源重建后标志与真实几何一致。
- 多个独立消费者读取标志不相互覆盖；不存在热路径反射、逐像素遍历所有灯或逐帧 CPU 回读顶点。

不要把该请求扩展成重写主框架或修改其它 Mod；本会话没有操作主仓库，也未给其他会话发送指令，由用户转交。
